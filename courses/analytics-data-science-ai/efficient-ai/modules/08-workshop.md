# Module 08 — Workshop: Your AI Roadmap

The interactive part of the session. Work in cross-functional teams of 3–5.

## Steps (about 60 minutes)

1. **List pain points (10 min).** Each person writes 3 problems from their area on sticky notes, using the problem statement template (`templates/problem-statement.md`), with no technology words.
2. **Size them (10 min).** Volume × time × % improvement × rate, plus waste. Rough is fine.
3. **Simplest countermeasure (10 min).** For each one: eliminate? standardize? rules? Only then ML or GenAI.
4. **Data readiness (10 min).** Score data readiness 1–5 with the checklist (`templates/data-readiness-checklist.md`); note the main gap.
5. **PICK chart (10 min).** Plot value vs feasibility; agree 1–2 pilots, 1 process fix and 1 foundation project.
6. **Roadmap and measures (10 min).** Fill `templates/ai-roadmap.md`: phase, owner, success measures, first step next week.

## Self-check before leaving

- [ ] Every idea starts from a problem with a number on it.
- [ ] At least one idea was resolved without AI.
- [ ] Each pilot has a baseline, an acceptance criterion and an owner.
- [ ] Data gaps have a process fix, not only a one-off cleanup.
- [ ] Risks (bias, privacy, over-trust) are noted for each pilot, with a countermeasure.

## Skill check

1. In one sentence, what is AI, and what is it not?
2. Give one pain point where AI fits and one where it doesn't, and say why.
3. Name three reasons AI initiatives fail and a Lean countermeasure for each.
4. Name four data-quality dimensions.
5. What goes into a phased AI roadmap?

<details><summary>Answers</summary>

1. Software that learns patterns from data to predict, classify or generate. It is probabilistic, not a fix for a broken process, and not right every time.
2. Fits: routing 24,000 tickets a year with good historical labels (a repeated decision, pattern-based, errors caught). Doesn't fit: chasing approvals, which is a process design problem (fix the workflow).
3. Any three, for example: wrong problem → problem statement and value-stream mapping; data issues → readiness check and process fix; low adoption → co-design and fitting the tool into standard work; over-trust → error-proofing and review standards.
4. Completeness, validity, consistency, uniqueness. Also timeliness, accuracy and label availability.
5. Prioritized initiatives in phases (process fixes now, pilots, quick wins, foundations), with owners, success measures, gates and governance.
